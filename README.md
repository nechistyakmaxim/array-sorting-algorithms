
# Сортировка массивов. Пузырьки, выборы и вставки — магия порядка в хаосе
Сортировка данных — одна из фундаментальных задач в программировании. Понимание принципов сортировки открывает путь к созданию эффективных и производительных программ.

## Что такое массив и зачем его сортировать?

**Массив** в 1С: Элемент  — это упорядоченная коллекция элементов, где каждый элемент имеет свой индекс (начиная с нуля). Можно представить массив как набор пронумерованных ячеек, содержащих данные.

```
знч МойМассив = [5, 3, 8, 1, 2] // Массив из пяти числовых элементов
```

**Сортировка** — это процесс упорядочивания элементов массива по определенному критерию (возрастание, убывание, алфавитный порядок). Необходимость сортировки возникает во множестве scenarios:

- **Эффективный поиск:** В отсортированном массиве можно использовать быстрые алгоритмы поиска, такие как бинарный поиск 
- **Удобство представления:** Пользователям проще работать с упорядоченными данными (контакты, товары, документы)
- **Анализ данных:** Многие статистические операции требуют предварительной сортировки данных

Рассмотрим классические алгоритмы сортировки, лежащие в основе более сложных современных решений.

## Сортировка пузырьком (Bubble Sort)

### Принцип работы

Алгоритм получил название по аналогии с пузырьками воздуха, которые всплывают в жидкости. В процессе сортировки более легкие элементы постепенно "всплывают" к началу массива, а тяжелые — "оседают" в конец.

Алгоритм многократно проходит по массиву, сравнивая соседние элементы и меняя их местами, если они расположены в неправильном порядке. Каждый проход перемещает очередной наибольший элемент на его окончательную позицию.

### Пошаговый разбор на примере `[5, 3, 8, 1, 2]`

**Первый проход:**

1. Сравнение `5` и `3`: `5 > 3`, производится обмен → `[3, 5, 8, 1, 2]`
2. Сравнение `5` и `8`: `5 < 8`, порядок сохраняется → `[3, 5, 8, 1, 2]`
3. Сравнение `8` и `1`: `8 > 1`, производится обмен → `[3, 5, 1, 8, 2]`
4. Сравнение `8` и `2`: `8 > 2`, производится обмен → `[3, 5, 1, 2, 8]`

Наибольший элемент (8) занял свою окончательную позицию.

**Второй проход:**  
`[3, 5, 1, 2, 8]` → `[3, 1, 5, 2, 8]` → `[3, 1, 2, 5, 8]` → `[3, 1, 2, 5, 8]`

**Третий проход:**  
`[1, 3, 2, 5, 8]` → `[1, 2, 3, 5, 8]` → массив отсортирован

### Реализация на 1С: Элемент

```
метод Скрипт()
    // Исходный массив
    знч МойМассив = [5, 3, 8, 1, 2]
    ПузырьковаяСортировка(МойМассив)
;

@Локально
метод ПузырьковаяСортировка(МойМассив: Массив<Число>)
    знч ДлинаМассива = МойМассив.Граница() 
    // Внешний цикл — количество проходов по массиву:
    // -1 во внешнем цикле: потому что нужно N-1 проходов для N элементов
    для i = 0 по ДлинаМассива - 1   
        пер БылиПерестановки = Ложь
        // Внутренний цикл — сравнение соседних элементов:
        // -1 во внутреннем цикле: потому что сравниваем пары [j] и [j+1]
        // -i во внутреннем цикле: оптимизация - не проверяем уже отсортированные элементы в конце массива
        для j = 0 по ДлинаМассива - 1 - i 
            если МойМассив[j] > МойМассив[j + 1]
                // Элементы стоят не по порядку — меняем местами
                знч ВременноеЗначение = МойМассив[j]
                МойМассив[j] = МойМассив[j + 1]
                МойМассив[j + 1] = ВременноеЗначение
                БылиПерестановки = Истина
            ;
        ; 
        // Если не было ни одной перестановки — массив уже отсортирован, продолжать не нужно
        если не БылиПерестановки
            прервать
        ;
        // Выводим состояние массива после каждого прохода
        Консоль.Записать("Результат ${i+1} прохода: $МойМассив")    
    ;  
;
```

Результат использования:
```
Результат 1 прохода: [3, 5, 1, 2, 8]
Результат 2 прохода: [3, 1, 2, 5, 8]
Результат 3 прохода: [1, 2, 3, 5, 8]
```

### Эффективность алгоритма

#### Сложность по времени

- **Худший случай:** O(n²) — когда массив отсортирован в обратном порядке
- **Лучший случай:** O(n) — когда массив уже отсортирован (благодаря оптимизации с прерыванием)
- **Средний случай:** O(n²)

#### Сложность по памяти

- **O(1)** — алгоритм работает "на месте", не требуя дополнительной памяти

> [!NOTE] Выводы
> 
> - **Преимущества:** Простота понимания и реализации. Подходит для демонстрации базовых принципов сортировки.
> - **Недостатки:** Низкая эффективность на больших массивах. Количество операций растет квадратично с увеличением размера данных.
> - **Применимость:** Используется преимущественно в образовательных целях. Может быть полезен для сортировки очень малых массивов (5-10 элементов).

## Сортировка выбором (Selection Sort)

Сортировка выбором — это интуитивно понятный алгоритм, который имитирует способ сортировки, используемый человеком при работе с небольшими наборами данных. Его простота и предсказуемость делают его отличным инструментом для изучения основ алгоритмов сортировки.

### Принцип работы

Представьте, что вам нужно разложить колоду карт по порядку. Вы ищете самую младшую карту, кладете ее в начало, затем ищете следующую самую младшую из оставшихся, и так далее. Именно так работает сортировка выбором.

Алгоритм делит массив на две части:
- **Отсортированная часть** — в начале массива
- **Неотсортированная часть** — оставшиеся элементы

На каждом шаге алгоритм находит минимальный элемент в неотсортированной части и перемещает его в конец отсортированной части.

### Пошаговый разбор на примере `[5, 3, 8, 1, 2]`

1. **Первый проход:** Минимальный элемент во всем массиве — `1`. Обмен с первым элементом (`5`) → `[1, 3, 8, 5, 2]`. Отсортированная часть: `[1]`
2. **Второй проход:** Минимальный элемент в `[3, 8, 5, 2]` — `2`. Обмен с `3` → `[1, 2, 8, 5, 3]`. Отсортированная часть: `[1, 2]`
3. **Третий проход:** Минимальный элемент в `[8, 5, 3]` — `3`. Обмен с `8` → `[1, 2, 3, 5, 8]`
4. **Четвертый проход:** Минимальный элемент в `[5, 8]` — `5`. Элемент уже на позиции. Массив отсортирован.

### Реализация на 1С: Элемент

```
метод Скрипт()
    // Исходный массив
    знч МойМассив = [5, 3, 8, 1, 2]
    СортировкаВыбором(МойМассив)
;

@Локально
метод СортировкаВыбором(МойМассив: Массив<Число>)
    знч ДлинаМассива = МойМассив.Размер() 
    // Внешний цикл — проходим по каждому элементу массива
    // После i-го прохода первые i элементов уже отсортированы
    для i = 0 по ДлинаМассива - 2   
        // Считаем текущий элемент минимальным
        пер ИндексМинимальногоЭлемента = i
        // Внутренний цикл — ищем минимальный элемент в оставшейся части массива
        для j = i + 1 по ДлинаМассива - 1  
            если МойМассив[j] < МойМассив[ИндексМинимальногоЭлемента]
                ИндексМинимальногоЭлемента = j // Запоминаем индекс найденного минимума
            ;
        ; 
        // Если нашли элемент меньше текущего — меняем их местами
        если i != ИндексМинимальногоЭлемента
            знч ВременноеЗначение = МойМассив[i]
            МойМассив[i] = МойМассив[ИндексМинимальногоЭлемента]
            МойМассив[ИндексМинимальногоЭлемента] = ВременноеЗначение
        ;
        // Выводим состояние массива после каждого прохода
        Консоль.Записать("Результат ${i+1} прохода: $МойМассив")    
    ;  
;
```

Результат
```
Результат 1 прохода: [1, 3, 8, 5, 2]
Результат 2 прохода: [1, 2, 8, 5, 3]
Результат 3 прохода: [1, 2, 3, 5, 8]
Результат 4 прохода: [1, 2, 3, 5, 8]
```

### Эффективность алгоритма

#### Сложность по времени

- **Худший случай:** O(n²)
- **Лучший случай:** O(n²)
- **Средний случай:** O(n²)
    
В отличие от пузырьковой сортировки, сортировка выбором всегда имеет квадратичную сложность, независимо от исходной упорядоченности данных.
#### Сложность по памяти

- **O(1)** — алгоритм работает "на месте", не требуя дополнительной памяти

### Количество операций

- **Сравнения:** всегда n(n-1)/2
- **Обмены:** не более n-1
### Выводы

- **Преимущества:** Простая реализация. Количество обменов минимально (не более n-1), что может быть важно при дорогостоящих операциях перемещения данных.
- **Недостатки:** Квадратичная сложность в лучшем, среднем и худшем случаях. Не адаптируется к частичной упорядоченности исходных данных.
- **Применимость:** Как и пузырьковая сортировка, используется в основном для обучения. Может применяться в средах с ограниченными ресурсами, где важна минимальность операций обмена.

## Сортировка вставками (Insertion Sort)

Сортировка вставками — это элегантный и интуитивно понятный алгоритм, который имитирует способ сортировки, используемый людьми при работе с картами или другими небольшими наборами объектов. Его эффективность на частично упорядоченных данных и простота реализации делают его одним из наиболее практичных простых алгоритмов сортировки.

### Суть алгоритма

Представьте, что вы держите в руке несколько отсортированных карт и получаете новую карту. Вы не пересматриваете всю руку заново, а просто находите правильное место для новой карты среди уже упорядоченных. Именно так работает сортировка вставками.

Алгоритм поддерживает две части массива:
- **Отсортированная часть** — в начале массива
- **Неотсортированная часть** — оставшиеся элементы

На каждом шаге алгоритм берет первый элемент из неотсортированной части и "вставляет" его в правильную позицию в отсортированной части.

### Пошаговый разбор на примере `[5, 3, 8, 1, 2]`

Начинаем со второго элемента (`3`), считая первый элемент (`5`) условно отсортированным.
1. **Элемент `3`:** Сравнение с `5`: `3 < 5`, вставка перед `5` → `[3, 5, 8, 1, 2]`
2. **Элемент `8`:** Сравнение с `5`: `8 > 5`, позиция сохранена → `[3, 5, 8, 1, 2]`
3. **Элемент `1`:** Поиск позиции в `[3, 5, 8]`: `1 < 8`, `1 < 5`, `1 < 3`, вставка в начало → `[1, 3, 5, 8, 2]`
4. **Элемент `2`:** Поиск позиции в `[1, 3, 5, 8]`: `2 < 8`, `2 < 5`, `2 < 3`, `2 > 1`, вставка после `1` → `[1, 2, 3, 5, 8]`

### Реализация на 1С: Элемент

```
метод Скрипт()
    // Исходный массив
    знч МойМассив = [5, 3, 8, 1, 2]
    СортировкаВставками(МойМассив)
;

@Локально
метод СортировкаВставками(МойМассив: Массив<Число>)
    знч ДлинаМассива = МойМассив.Размер() 
    // Внешний цикл — начинаем со второго элемента (первый считается отсортированным)
    для i = 1 по ДлинаМассива - 1   
        // Сохраняем текущий элемент, который будем вставлять
        пер ТекущийЭлементВставки = МойМассив[i]
        // Индекс для сравнения с предыдущими элементами
        пер j = i - 1
        // Сдвигаем элементы вправо, пока они больше вставляемого элемента
        пока j >= 0 и МойМассив[j] > ТекущийЭлементВставки
            МойМассив[j + 1] = МойМассив[j]
            j -= 1    // Переходим к предыдущему элементу
        ;
        // Вставляем текущий элемент на своё место
        МойМассив[j + 1] = ТекущийЭлементВставки
        // Выводим состояние массива после каждого прохода
        Консоль.Записать("Результат ${i+1} прохода: $МойМассив")    
    ;  
;
```

Результат
```
Результат 2 прохода: [3, 5, 8, 1, 2]
Результат 3 прохода: [3, 5, 8, 1, 2]
Результат 4 прохода: [1, 3, 5, 8, 2]
Результат 5 прохода: [1, 2, 3, 5, 8]
```

### Эффективность алгоритма

#### Сложность по времени

- **Худший случай:** O(n²) — когда массив отсортирован в обратном порядке
- **Лучший случай:** O(n) — когда массив уже отсортирован    
- **Средний случай:** O(n²)

#### Сложность по памяти

- **O(1)** — алгоритм работает "на месте", не требуя дополнительной памяти
#### Количество операций

- **Сравнения:** от n-1 (лучший случай) до n(n-1)/2 (худший случай)
- **Присваивания:** аналогично количеству сравнений
### Выводы

- **Преимущества:** Эффективен для малых и частично отсортированных массивов. Работает на месте без использования дополнительной памяти. В лучшем случае (уже отсортированный массив) имеет линейную сложность.
- **Недостатки:** Квадратичная сложность в худшем случае. Неэффективен для больших неупорядоченных массивов.
- **Применимость:** Имеет практическое применение. Часто используется как составная часть более сложных алгоритмов (например, в TimSort) для сортировки небольших подмассивов.

## Быстрая сортировка (QuickSort)

### Принцип работы

Быстрая сортировка использует стратегию "разделяй и властвуй". Алгоритм выбирает опорный элемент и перераспределяет другие элементы таким образом, чтобы меньшие оказались слева от опоры, а большие — справа. Затем рекурсивно применяет тот же подход к образовавшимся подмассивам.

### Упрощенный пошаговый разбор на примере `[5, 3, 8, 1, 2]`

1. **Выбор опоры:** Опорный элемент — `2` (последний элемент)
2. **Разделение:** Элементы меньше или равные опоре: `[1]`. Элементы больше опоры: `[5, 3, 8]`. Опорный элемент размещается между ними → `[1, 2, 5, 3, 8]`
3. **Рекурсия:** Сортировка левой части `[1]` (уже отсортирована) и правой части `[5, 3, 8]`
    - Для `[5, 3, 8]` опора — `8`
    - Разделение: `[5, 3]` (меньшие) и `[]` (большие) → `[5, 3, 8]`
    - Сортировка `[5, 3]`: опора — `3`, разделение: `[]` и `[5]` → `[3, 5]`
4. **Объединение:** `[1]` + `[2]` + `[3, 5]` + `[8]` = `[1, 2, 3, 5, 8]`

### Реализация на 1С: Элемент (упрощенная версия)

```
метод Скрипт()
    // Исходный массив для сортировки
    знч МойМассив = [5, 3, 8, 1, 2]
    // Запускаем быструю сортировку на массиве
    БыстраяСортировка(МойМассив)
;
 
@Локально
метод БыстраяСортировка(МойМассив: Массив<Число>): Массив<Число>
    // Базовый случай рекурсии:
    // если массив пустой или содержит один элемент, он уже отсортирован
    если МойМассив.Размер() <= 1
        возврат МойМассив
    ;

    // Выбираем опорный элемент для разделения массива
    // Можно выбрать последний, первый или случайный элемент
    пер pivotIndex = (МойМассив.Размер() / 2).ЦелаяЧасть()
    пер pivot = МойМассив[pivotIndex]

    // Создаем три массива:
    // МеньшеОпорного — элементы меньше pivot
    // Равно — элементы, равные pivot (включая сам pivot)
    // БольшеОпорного — элементы больше pivot
    знч МеньшеОпорного = <Число>[]
    знч Равно = <Число>[]
    знч БольшеОпорного = <Число>[]

    // Распределяем элементы исходного массива по трём подмассивам
    для i = 0 по МойМассив.Размер() - 1
        если МойМассив[i] < pivot
            МеньшеОпорного.Добавить(МойМассив[i])
        иначе если МойМассив[i] == pivot
            Равно.Добавить(МойМассив[i])
        иначе
            БольшеОпорного.Добавить(МойМассив[i])
        ;
    ;

    // Рекурсивно сортируем подмассивы "меньше" и "больше",
    // затем объединяем отсортированные части и элементы, равные pivot
    знч Результат = БыстраяСортировка(МеньшеОпорного)
        .Объединить(Равно)
        .Объединить(БыстраяСортировка(БольшеОпорного))
    
    // Выводим промежуточный результат для демонстрации работы алгоритма
    Консоль.Записать("Промежуточный результат: $Результат")
        
    // Возвращаем отсортированный массив
    возврат Результат
;
```

Результат:
```
Промежуточный результат: [2, 3, 5]
Промежуточный результат: [1, 2, 3, 5]
Промежуточный результат: [1, 2, 3, 5, 8]
```

_Примечание: Данная реализация демонстрирует принцип работы алгоритма, но не является оптимальной по использованию памяти. Промышленные реализации используют модификацию массива на месте._

### Почему QuickSort — «быстрая»?

Потому что в **среднем случае** он работает за **O(n log n)** — почти так же быстро, как теоретически возможно для сортировки сравнениями.

Сравните:

- Пузырьковая сортировка: O(n²) → при 1000 элементах — ~1 000 000 операций.
- QuickSort: O(n log n) → при 1000 элементах — ~10 000 операций.

Разница — в **100 раз**!

#### Но есть нюансы… Худший случай: O(n²)

Если массив **уже отсортирован**, и вы всегда выбираете **последний элемент как pivot**, то:

- массив `МеньшеОпорного` будет пустым,
- массив `БольшеОпорного` — почти весь массив.

Разделение получится **очень несбалансированным**, и глубина рекурсии станет **n**. Это приведёт к O(n²).

**Как избежать?**

- Выбирать pivot **случайно**.
- Использовать **медиану трёх** (первый, средний, последний).
- В промышленных реализациях — переключаться на другие алгоритмы при глубокой рекурсии (например, Introsort).
### Выводы

- **Преимущества:** Один из самых эффективных алгоритмов сортировки общего назначения. В среднем случае имеет сложность O(n log n).
- **Недостатки:** В худшем случае (неудачный выбор опорного элемента) деградирует до O(n²). Рекурсивная реализация может привести к переполнению стека вызовов.
- **Применимость:** Широко используется на практике. Входит в стандартные библиотеки многих языков программирования.

## Встроенная сортировка в современных языках программирования

Практически во всех современных языках программирования стандартная библиотека предоставляет готовый метод для сортировки массивов или списков. Однако важно понимать, **как он работает и какие нюансы нужно учитывать**.

Что особенно интересно — **внутри стандартного метода сортировки** почти никогда не используется один из простых алгоритмов вроде пузырьковой или быстрой сортировки. Вместо этого современные реализации (например, в V8 (движок JavaScript, используемый в Chrome и Node.js), Java, Python и других средах) применяют **сложные гибридные алгоритмы**, такие как **Timsort**.

**Timsort** — это умный гибрид, сочетающий:

- **сортировку вставками** для небольших участков данных (где она очень эффективна),
- **сортировку слиянием** для объединения уже упорядоченных фрагментов.

Такой подход особенно эффективен на **реальных данных**, которые часто содержат частично упорядоченные последовательности (например, логи по времени, списки контактов, результаты поиска). Благодаря этому встроенная сортировка работает быстро, стабильно и предсказуемо — даже если вы не задумываетесь об алгоритмах «под капотом».

## Ценность изучения базовых алгоритмов

Возникает закономерный вопрос: зачем изучать простые алгоритмы, если существуют готовые оптимизированные реализации?

1. **Фундаментальные знания:** Базовые алгоритмы формируют понимание принципов обработки данных и анализа сложности алгоритмов (О-нотация)
2. **Развитие алгоритмического мышления:** Умение реализовать и анализировать простые алгоритмы создает основу для понимания более сложных концепций
3. **Специализированные применения:** В условиях строгих ограничений (встроенные системы, микроконтроллеры) иногда необходимы простые и предсказуемые решения

Изучение базовых алгоритмов сортировки — это не только освоение конкретных техник, но и развитие системного подхода к решению computational задач.
